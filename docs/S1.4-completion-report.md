3. Implemented Capabilities Checklist
Architecture Integration
 Strict Layer Decoupling: Transfer logic rests purely above Session. The lower-level Transport remains decoupled from application-level file semantics.
 Module Isolation: All file manipulation, progress tracking, parsing, and cryptographic checks are housed within crates/flux-core/src/transfer/.
Transfer Protocol FSM
 Metadata Negotiations: File exchanges begin with detailed TransferRequest structures detailing TransferId, file_name, file_size, chunk_size, total_chunks, and sha256.
 Explicit Accept/Reject Mechanics: The receiver reserves the right to decline or drop requests on validation failure.
 Indexed Chunk Sequencing: All packets carry an explicit sequence index. The receiver validates sequential ordering on packet arrival.
File & Memory Safety
 Path Traversal Shield: Remote paths are parsed and sanitized, filtering out dangerous directory traversals and keeping files isolated inside the local sandbox directory (received/).
 Incomplete Block Shield: Files are written to a .part extension during the live state. Incomplete or failed transfers are wiped from the filesystem, avoiding corruption.
 Linear RAM Scaling: Streaming buffers enforce constant, low-RAM consumption (defaulting to 64 KiB), ensuring Aryntra Flux can run easily on edge systems.
Cryptographic Assurance
 Integrity Verification: Receiver performs live SHA-256 calculation of arriving chunks, verifying the calculated digest with the metadata payload on completion.
