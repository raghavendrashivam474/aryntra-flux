## 2. Deliverables & Capabilities Added

### 2.1 Path Telemetry & Expiry Model (`crates/flux-core/src/path/metrics.rs` & `mod.rs`)
- **`PathMetrics`**: Decoupled latency and reachability record storing `rtt_ms: Option<u64>` and `last_probed: Option<Instant>`.
- **`PathId` Ordering**: Derived `PartialOrd, Ord` on `PathId` to guarantee deterministic tie-breaking across path sets.
- **Stale Expiry Policy**: Added `is_stale_at()` and `expire_stale_paths_at()` on `PathSet` and `PathRegistry` to transition unrefreshed candidate routes to `PathState::Unavailable` past a configured TTL.

### 2.2 Active Probing Engine (`crates/flux-core/src/path/prober.rs`)
- **`PathProber`**: Actively validates reachability by establishing sessions using the existing `SessionBuilder` and executing non-intrusive Ping/Pong frame exchanges.
- **State Machine Integration**:
  - Connecting $\to$ `PathState::Connecting`
  - Successful Pong response $\to$ `PathState::Available` + `PathMetrics::with_rtt(rtt)`
  - Connection/Ping timeout or socket error $\to$ `PathState::Unavailable`

### 2.3 Deterministic Path Selector (`crates/flux-core/src/path/selector.rs`)
- **`PathSelector`**: Pure, deterministic selection algorithm:
  1. Filters paths strictly to `PathState::Available`.
  2. Requires valid, recorded `rtt_ms` measurements.
  3. Selects the minimum RTT route.
  4. Resolves ties using stable `PathId` lexical comparison.

### 2.4 End-to-End Multi-Path Verification (`crates/flux-core/tests/path_measurement_selection_test.rs`)
- Spins up real concurrent TCP listeners on distinct endpoints with simulated latency variations.
- Validates that `PathProber` concurrently evaluates all routes, records real RTT metrics, marks dead ports `Unavailable`, and causes `PathSelector` to pick the optimal route.

### 2.5 Architecture Documentation (`docs/decisions/0011-path-measurement.md`)
- Documented design decisions, invariants, and boundaries in ADR-0011.
